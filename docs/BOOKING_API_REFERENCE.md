# Class Clinic Booking API — เอกสารสำหรับ Saifa AI (v1)

เอกสารนี้บอกว่า "เรียกอะไร ส่งอะไร ได้อะไรกลับมา" เพื่อให้น้องคลาสเช็กคิวและจองคิวลงระบบ Class Clinic ได้จบในแชท

## 1. การเชื่อมต่อ
- **Base URL:** `https://hjuvtsjjtucdirlkdgwa.supabase.co/functions/v1/booking-api`
- **HTTPS เท่านั้น** · `Content-Type: application/json` (UTF-8) · เรียกจากเซิร์ฟเวอร์เท่านั้น (ไม่รองรับเบราว์เซอร์/CORS)
- **ยืนยันตัวตน:** header `X-API-Key: <key>` — มี 2 คีย์ใช้ URL เดียวกัน
  - **sandbox** — เช็กคิวจากข้อมูลจริง แต่ `POST /v1/bookings` ตรวจเงื่อนไขครบแล้ว **ไม่สร้างคิวจริง** คืน `booking_id` เป็น `SANDBOX-…`
  - **production** — จองลงระบบจริง
- เวลาใช้ ISO 8601 พร้อมโซนเวลา (แนะนำ `+07:00`) เวลาที่ตอบกลับเป็น `+07:00` เสมอ
- เป้าหมายเวลาตอบ ≤ 2 วินาที (p95); จำกัดอัตรา: จอง 30 ครั้ง/นาที, เช็ก/ช่องเวลา 300 ครั้ง/นาที, รายการสาขา 60 ครั้ง/นาที (เกิน = `429 RATE_LIMITED`)

## 2. รูปแบบข้อผิดพลาด (ทุก endpoint)
```json
{ "success": false, "error_code": "INVALID_SKU", "message": "ไม่รู้จักรหัสบริการ (SKU)" }
```
| HTTP | `error_code` | เมื่อไหร่ |
|---|---|---|
| 401 | `UNAUTHORIZED` | ไม่ส่งหรือส่ง API key ผิด |
| 404 / 405 | `NOT_FOUND` / `METHOD_NOT_ALLOWED` | endpoint หรือ method ไม่ถูก |
| 422 | `INVALID_REQUEST` | body ไม่ใช่ JSON object / ว่าง / ใหญ่เกิน 8 KB |
| 422 | `INVALID_BRANCH` | ไม่รู้จักรหัสสาขา |
| 422 | `INVALID_SKU` | ไม่รู้จัก SKU หรือยังไม่เปิดให้จอง |
| 422 | `INVALID_TIME` | เวลาไม่มีโซนเวลา / รูปแบบผิด / นาทีไม่ใช่พหุคูณของ 5 |
| 422 | `INVALID_CUSTOMER` | ชื่อว่าง/ยาวเกิน 100, เบอร์ไม่ใช่เบอร์ไทย (มือถือ 10 หลักขึ้นต้น 06/08/09 หรือเบอร์บ้าน 9 หลักขึ้นต้น 02–07; รับ +66 และขีด/เว้นวรรคได้), `type` ไม่ใช่ `new`/`old` |
| 422 | `INVALID_REFERENCE` | `reference_id` ไม่ใช่ตัวอักษร ตัวเลข `_` `-` ยาว 1–64 ตัว |
| 422 | `OUTSIDE_BOOKING_WINDOW` | จองก่อนเวลานัดน้อยกว่า 2 ชั่วโมง หรือล่วงหน้าเกิน 60 วัน |
| 422 | `PAST_TIME` | เวลาที่ขอผ่านมาแล้ว |
| 422 | `SERVICE_NOT_AT_BRANCH` | สาขานี้ไม่มีบริการนี้ |
| 422 | `BRANCH_NOT_ACCEPTING` | สาขานี้ปิดรับจองผ่านระบบอยู่ |
| 409 | `SLOT_UNAVAILABLE` | คิวไม่ว่าง/ถูกจองไปแล้วระหว่างที่ลูกค้ากำลังยืนยัน (มี `alternatives`) |
| 409 | `REFERENCE_ID_REUSED` | `reference_id` นี้เคยใช้กับข้อมูลการจองอื่นแล้ว |
| 429 | `RATE_LIMITED` | เรียกถี่เกินไป |
| 5xx | `INTERNAL_ERROR` | ระบบคลินิกขัดข้อง — ให้ AI ส่งเรื่องต่อแอดมินตามที่ตกลง |

## 3. `GET /v1/branches` — รายการสาขา
คืนรหัสสาขาทุกสาขาที่มีรหัส พร้อมสถานะเปิดรับจอง (เรียกตอนเริ่มระบบหรือวันละครั้งเพื่อให้รายการสาขาตรงกับของคลินิกเสมอ)
```json
{ "branches": [ { "code": "KK", "name": "Class Go กังสดาล", "active": true }, … ] }
```
สาขาใหม่ของคลินิกจะ **ยังไม่ปรากฏ** จนกว่าคลินิกจะเพิ่มรหัสให้ · `active: false` = ปิดรับจอง

## 3.1 `GET /v1/catalog` — รายการ SKU (บริการ/โปร) ที่จองได้
คลินิก **ออกรหัส SKU ให้เอง** จากโปรโมชันในระบบ (รูปแบบ `PM-` ตามด้วยรหัส 10 ตัว คงที่ตลอด ไม่เปลี่ยนแม้แก้ชื่อหรือราคา) ฝั่ง Saifa จับคู่สินค้าของตนกับรหัสเหล่านี้ (ไฟล์ CSV แนบมาพร้อมเอกสาร หรือดึงล่าสุดจาก endpoint นี้)
```json
{ "skus": [ { "sku": "PM-049D58F87E", "name": "hifu 990", "price": 990, "service": "Hifu",
              "category": "Hifu", "duration_minutes": 40, "scope": "standard" }, … ] }
```
- `price` = ราคาโปรเป็นบาท (ลงคิวพร้อมราคานี้) · `duration_minutes` = ความยาวคิวที่ระบบจองให้
- `scope`: `standard` = ใช้ได้ที่สาขาทั่วไป · `class_go` = ใช้ได้เฉพาะสาขา Class Go (KK, KC, BN) — ใช้ผิดกลุ่ม = `SERVICE_NOT_AT_BRANCH`
- **โปรใหม่ที่คลินิกเพิ่มจะปรากฏที่นี่เองทันที** (ไม่ต้องแจ้งหรือจับคู่เพิ่มฝั่งคลินิก) โปรที่ปิดหรือถูกคลินิกถอดออกจะหายจากรายการ และ SKU นั้นตอบ `INVALID_SKU` — แนะนำให้ดึงรายการนี้วันละครั้ง
- ไม่มีโปรราคา 0 (เช่น ใช้คอร์ส, ปรึกษา, โปรไลฟ์ที่ระบุราคาในชื่อ) ในรายการ
- SKU ทดสอบสำหรับ sandbox (ใช้กับ sandbox key เท่านั้น จองจริงไม่ได้): `TEST-HIFU`, `TEST-BOTOX`, `TEST-FILLER`, `TEST-DIODE`, `TEST-DRIP`, `TEST-PEN`, `TEST-MESO`, `TEST-CONSULT`

## 4. `POST /v1/availability/check` — เช็กคิวว่าง
```json
{ "branch_code": "KK", "sku": "HIFU-100", "start_time": "2026-10-05T14:00:00+07:00" }
```
ว่าง → `200 { "available": true }`
ไม่ว่าง → `200` พร้อมเหตุผลและเวลาทางเลือก (วันเดียวกัน ตาราง 30 นาที ไม่เกิน 3 ช่วง เรียงเวลา)
```json
{ "available": false, "reason": "SLOT_FULL",
  "alternatives": ["2026-10-05T15:00:00+07:00", "2026-10-05T16:30:00+07:00"] }
```
| `reason` | ความหมาย |
|---|---|
| `SLOT_FULL` | ห้องที่ทำบริการนี้ได้มีคิวชนในช่วงเวลานั้น |
| `OUTSIDE_HOURS` | ไม่มีห้องไหนเปิดในช่วงเวลานั้น (นอกเวลา หรือวันปิด) |
| `SERVICE_NOT_AT_BRANCH` | สาขานี้ไม่มีบริการนี้ |
| `OUTSIDE_BOOKING_WINDOW` | ก่อนเวลานัดน้อยกว่า 2 ชั่วโมง หรือล่วงหน้าเกิน 60 วัน (ไม่มี alternatives) |
| `PAST_TIME` | เวลาผ่านมาแล้ว |
| `BRANCH_NOT_ACCEPTING` | สาขานี้ปิดรับจองผ่านระบบ |

หมายเหตุ: คิวเริ่มได้ทุก 5 นาที ความยาวคิวขึ้นกับบริการ (ระบบคำนวณเอง) การเช็กว่า "ว่าง" หมายถึงมีห้องว่างตลอดช่วงของบริการนั้น

## 5. `GET /v1/availability/slots?branch_code=KK&sku=HIFU-100&date=2026-10-05` — ช่องว่างทั้งวัน
```json
{ "date": "2026-10-05",
  "slots": [ { "start_time": "2026-10-05T11:30:00+07:00", "available": true },
             { "start_time": "2026-10-05T12:00:00+07:00", "available": false } ] }
```
ทุกช่อง 30 นาทีในช่วงเวลาทำการของสาขาวันนั้น (ช่องที่เกินกติกา 2 ชั่วโมง/60 วันจะเป็น `available: false`) ใช้ตอนลูกค้าถามกว้าง ๆ เช่น "พรุ่งนี้ว่างกี่โมง"

## 6. `POST /v1/bookings` — จองคิว
```json
{
  "reference_id": "saifa_7f3a9c21",
  "branch_code": "KK",
  "sku": "HIFU-100",
  "start_time": "2026-10-05T14:00:00+07:00",
  "customer": { "name": "สมชาย ใจดี", "phone": "0812345678", "type": "new" },
  "note": "ลูกค้าใหม่ จองผ่านแชท Facebook"
}
```
| ฟิลด์ | | คำอธิบาย |
|---|---|---|
| `reference_id` | จำเป็น | รหัสอ้างอิงจาก Saifa ไม่ซ้ำต่อการจอง |
| `branch_code`, `sku`, `start_time` | จำเป็น | เหมือน `/availability/check` |
| `customer.name` / `customer.phone` | จำเป็น | ชื่อและเบอร์ของผู้มารับบริการ |
| `customer.type` | **จำเป็น** | `"new"` ลูกค้าใหม่ หรือ `"old"` ลูกค้าเก่า — **น้องคลาสต้องถามลูกค้าก่อนจอง** (คลินิกใช้คำนวณค่าคอมมิชชัน) |
| `note` | ไม่บังคับ | ข้อความเพิ่มเติมจากแชท (ไม่เกิน 500 ตัวอักษร) |

**สำเร็จ — `201`**
```json
{ "success": true, "booking_id": "CC-20261005-0142", "status": "confirmed",
  "branch_code": "KK", "sku": "HIFU-100", "start_time": "2026-10-05T14:00:00+07:00" }
```
- `status: "confirmed"` = **ระบบจองห้อง/เวลาให้แล้วทันที** แอดมินเห็นในหน้าคิวของสาขา (ผู้บันทึกคือ "น้องคลาส Ai") ขั้นตอนโทรย้ำนัดตามปกติของคลินิกเป็นเรื่องภายในของเรา ไม่ต้องแจ้งลูกค้าว่ารอยืนยัน
- เวลา `start_time` ที่ตอบกลับเป็น `+07:00` เสมอ; `booking_id` รูปแบบ `CC-<วันนัด>-<เลขรัน>` (sandbox: `SANDBOX-…`)

**คิวไม่ว่าง — `409`**
```json
{ "success": false, "error_code": "SLOT_UNAVAILABLE", "message": "คิวเวลานี้ถูกจองไปแล้วหรือไม่ว่าง",
  "alternatives": ["2026-10-05T15:00:00+07:00"] }
```

### การส่งซ้ำ (เน็ตหลุด / timeout)
ส่ง `reference_id` เดิมซ้ำ **ด้วยข้อมูลเดิมเป๊ะ** → ได้ผลการจองเดิมกลับมา (HTTP 201) **ไม่สร้างคิวซ้ำ** · ส่ง `reference_id` เดิมแต่ข้อมูลต่าง → `409 REFERENCE_ID_REUSED` (ถ้าลูกค้าเปลี่ยนใจเรื่องเวลา ให้สร้าง `reference_id` ใหม่)

## 7. กติกาสรุป
- จองได้ **ไม่เกิน 60 วัน** ล่วงหน้า และต้อง **ก่อนเวลานัดอย่างน้อย 2 ชั่วโมง** (เวลาไทย)
- **1 คิว = 1 บริการ (1 SKU)** — ลูกค้าจองหลายบริการให้เรียกจองหลายครั้ง คนละ `reference_id`
- คลินิกจัดห้องให้เอง (ผู้เรียกไม่ต้องระบุห้อง) · คลินิกตรวจโควตา/เงื่อนไขของโปรตอนโทรย้ำนัด
- ไม่มี `NO_DOCTOR` และ `PROMO_QUOTA_FULL` ในเวอร์ชันนี้
- ยังไม่มีเลื่อน/ยกเลิก/webhook (ยกเลิกหรือเลื่อน ให้ AI ส่งเรื่องต่อแอดมิน)

## 9. ตัวอย่างเรียกด้วย curl
```bash
curl -X POST "$BASE/v1/availability/check" \
  -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"branch_code":"KK","sku":"HIFU-100","start_time":"2026-10-05T14:00:00+07:00"}'
```

## 10. ที่จะแจ้งให้ทราบ
- รายการ SKU เปลี่ยนตามโปรของคลินิก (ดู `GET /v1/catalog`) · SKU ที่ไม่อยู่ในรายการตอบ `INVALID_SKU`
- สาขาใหม่หรือสาขาที่ปิดรับ → ดูจาก `GET /v1/branches`
